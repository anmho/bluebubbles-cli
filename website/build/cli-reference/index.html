Output options​

Most API commands support:

  • -o, --output <format> where format is table, wide, or json
  • --json as an alias for -o json
  • -v, --verbose for API diagnostics to stderr

Endpoint-mapped commands​

Ping​

  • bluebubbles ping API: GET /api/v1/ping

Server​

  • bluebubbles server info API: GET /api/v1/server/info
  • bluebubbles server logs [--count <n>] Local process manager, no API endpoint
  • bluebubbles server logs --source api [--count <n>] API: GET /api/v1/server/logs
  • bluebubbles server open Local process manager, no API endpoint
  • bluebubbles server start Local process manager, no API endpoint
  • bluebubbles server status Local process manager, no API endpoint
  • bluebubbles server stop [--yes] Local process manager, no API endpoint
  • bluebubbles server restart [--yes] Local process manager, no API endpoint
  • bluebubbles server alert list API: GET /api/v1/server/alert
  • bluebubbles server alert read <ids> API: POST /api/v1/server/alert/read
  • bluebubbles server update check API: GET /api/v1/server/update/check
  • bluebubbles server update install [--wait] [--yes] API: POST /api/v1/server/update/install
  • bluebubbles server restart-services [--yes] API: GET /api/v1/server/restart/soft
  • bluebubbles server restart-app [--yes] API: GET /api/v1/server/restart/hard
  • bluebubbles server settings get API: GET /api/v1/backup/settings
  • bluebubbles server settings set --file <path> API: POST /api/v1/backup/settings
  • bluebubbles server settings delete <name> [--yes] API: DELETE /api/v1/backup/settings/<name>
  • bluebubbles server theme list API: GET /api/v1/backup/theme
  • bluebubbles server theme set <name> --file <path> API: POST /api/v1/backup/theme
  • bluebubbles server theme delete <name> [--yes] API: DELETE /api/v1/backup/theme/<name>

Chat​

  • bluebubbles chats list API: POST /api/v1/chat/query
  • bluebubbles chats get <guid> API: GET /api/v1/chat/<Chat GUID>
  • bluebubbles chats messages <guid> API: GET /api/v1/chat/<Chat GUID>/message Notes: defaults to --limit 50; supports --after and --before
  • bluebubbles chats update <guid> --name <name> API: PUT /api/v1/chat/<Chat GUID>
  • bluebubbles chats delete <guid> [--yes] API: DELETE /api/v1/chat/<Chat GUID>
  • bluebubbles chats group leave <guid> [--yes] API: POST /api/v1/chat/<Chat GUID>/leave
  • bluebubbles chats group participant add <guid> <address> API: POST /api/v1/chat/<Chat GUID>/participant
  • bluebubbles chats group participant remove <guid> <address> [--yes] API: DELETE /api/v1/chat/<Chat GUID>/participant
  • bluebubbles chats group icon set <guid> API: POST /api/v1/chat/<Chat GUID>/icon
  • bluebubbles chats group icon remove <guid> [--yes] API: DELETE /api/v1/chat/<Chat GUID>/icon
  • bluebubbles chats typing start <guid> API: POST /api/v1/chat/<Chat GUID>/typing
  • bluebubbles chats typing stop <guid> API: DELETE /api/v1/chat/<Chat GUID>/typing

Message​

  • bluebubbles messages list API: POST /api/v1/message/query Notes: defaults to --limit 50; supports --chat, --after, --before, common filters (--text, --from, --from-me, --not-from-me, --has-attachments), and raw --where '<json>'. --text, --from, and --has-attachments are applied client-side to the returned page.
  • bluebubbles messages get <guid> API: GET /api/v1/message/<GUID>
  • bluebubbles messages send --chat <guid> --message <text> API: POST /api/v1/message/text
  • bluebubbles messages react <guid> --chat <guid> --reaction <type> API: POST /api/v1/message/react
  • bluebubbles messages edit <guid> --message <text> API: POST /api/v1/message/<GUID>/edit
  • bluebubbles messages unsend <guid> [--yes] API: POST /api/v1/message/<GUID>/unsend

Message Schedule​

  • bluebubbles messages schedule list API: GET /api/v1/message/schedule
  • bluebubbles messages schedule get <id> API: GET /api/v1/message/schedule/<ID>
  • bluebubbles messages schedule create --chat <guid> --message <text> --date <date> API: POST /api/v1/message/schedule
  • bluebubbles messages schedule update <id> API: PUT /api/v1/message/schedule/<ID>
  • bluebubbles messages schedule delete <id> [--yes] API: DELETE /api/v1/message/schedule/<ID>

Handle​

  • bluebubbles handle list API: POST /api/v1/handle/query
  • bluebubbles handle availability <address> API: GET /api/v1/handle/<address>/availability

Attachment​

  • bluebubbles attachment get <guid> API: GET /api/v1/attachment/<GUID>
  • bluebubbles attachment download <guid> [--file <path>] API: GET /api/v1/attachment/<GUID>/download
  • bluebubbles attachment force-download <guid> [--file <path>] API: GET /api/v1/attachment/<GUID>/download/force

Contact​

  • bluebubbles contact list API: GET /api/v1/contact
  • bluebubbles contact query [--address <value>] API: POST /api/v1/contact/query

iCloud​

  • bluebubbles icloud account API: GET /api/v1/icloud/account
  • bluebubbles icloud contact API: GET /api/v1/icloud/contact
  • bluebubbles icloud findmy devices list API: GET /api/v1/icloud/findmy/devices
  • bluebubbles icloud findmy devices refresh API: POST /api/v1/icloud/findmy/devices/refresh
  • bluebubbles icloud findmy friends list API: GET /api/v1/icloud/findmy/friends
  • bluebubbles icloud findmy friends refresh API: POST /api/v1/icloud/findmy/friends/refresh
  • bluebubbles icloud alias set <email> API: POST /api/v1/icloud/account/alias

Webhook​

  • bluebubbles webhook validate [file] Local tool, no API endpoint
  • bluebubbles webhook serve [--port <port>] [--path <path>] Local tool, no API endpoint

Removed from the curated surface​

  • fcm
  • mac
  • web-only commands
  • webhook types
  • low-value count and blurhash commands that are better handled with --json plus shell tools

Output​

Most commands accept --json and emit:

{
  "ok": true,
  "data": {}
}

Errors emit:

{
  "ok": false,
  "error": {
    "kind": "validation",
    "message": "..."
  }
}
